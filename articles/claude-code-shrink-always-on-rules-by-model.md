2026 年 7 月 25 日、自分の dotfiles で毎セッションの先頭に入っている指示を数えたら 139 行あった。

きっかけは Anthropic の [The new rules of context engineering for Claude 5 generation models](https://claude.com/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models) で、禁止の列挙ではなく判断を委ねる、事前一括ロードではなく段階的に開示する、同じ指示を 2 か所に書かない、といった原則が並んでいる。読みながら手元の CLAUDE.md と rules を開いたら、4 つの原則がそのまま当てはまった。

縮めること自体は 1 日で終わった。困ったのはそのあとで、削った指示はどこへ行くのか、という問いが残った。強制文を消したのは Claude 5 世代が手順を書かなくても判断できるという前提の上で、同じハーネスを別のモデルでも使う。旧世代で崩れる指示を、消したまま忘れていいのか。

## 139 行の内訳

Claude Code が作業内容によらず毎回読むのは、CLAUDE.md と、`rules/` のうち frontmatter に `paths:` を持たないファイルである。`paths:` があるものは対象ファイルを触るセッションでだけ展開されるので、数える対象から外した。

| 対象 | 行数 |
|---|---|
| CLAUDE.md | 59 |
| `paths:` を持たない rules 4 ファイル | 80 |
| 合計 | 139 |

rules は 6 ファイルあり、そのうち 4 ファイルに `paths:` が無かった。コメント規律、issue / PR の書き方、文章規律、そして「語より先に指示対象を固定する」という設計文向けの rule で、この最後の 1 つが 51 行と最も長かった。SQL も文書も書かないセッションでも、これらの本文全体が先頭に入っていた。

## 削ったもの

### 6 つの IMPORTANT

51 行の rule には `IMPORTANT:` で始まる文が 6 つあった。たとえばこう書いてあった。

> 対応表なしの本文提出は禁止。表なしで書き始めたら本文を破棄し、対応表から作り直す。

逸脱したときの処理まで指定している。守るべきなのは順序 (対応表が先) と、その順序が要る理由 (完成文書の先頭に表を置くだけでは生成順が変わらない) で、逸脱時に何をするかはモデルが決められる。理由と適用範囲だけを残し、強制文は全部消した。手順の詳細は呼び出し時にロードされる skill 側に同じ内容があったので、rule からは参照 1 文にした。51 行が 24 行になった。

### 読む側が居なかった要約ブロック

同じ rule の中に `<!-- codex-runtime-summary -->` というコメントで囲んだ要約ブロックがあった。Codex 向けに要点を抜き出しておく、という意図で置いたものだが、リポジトリ内でこの文字列を grep すると当該ファイル自身しか出てこない。読むスクリプトが存在しなかった。Codex は本文全体を読むので、要約は二重掲載になっているだけだった。消した。

### 効いていなかった側の重複

絵文字とセクション記号 (U+00A7) の禁止が、CLAUDE.md と `rules/doc-punctuation.md` の 2 か所に書いてあった。どちらかに寄せるとして、どちらを残すか。

見直して分かったのは、doc-punctuation.md は `paths: **/*.md` でスコープされているという点で、コミットメッセージやチャット応答には元々効いていなかった。実効ルールはずっと CLAUDE.md の側だった。重複の解消というより、片方は最初から重複の役をしていなかったことになる。CLAUDE.md に一本化し、doc-punctuation.md にはどちらが持つかを示す 1 行だけ残した。

### 止まりすぎる一文

CLAUDE.md には「ユーザからの指示や仕様に不明点があれば、作業を中断し質問する」と書いてあった。あらゆる不明点で止まる指示は、判断を委ねる方向と反対で、些細な選択でも作業が止まる。「読み方が分かれて成果物が変わる不明点は着手前に質問する。それ以外は自分で判断して進め、置いた前提を明示する」に変えた。

あわせて、成果物ルールの表組みを箇条書き 1 行にし、「仕様がテスト・型・実行可能なコードで表せるものは、散文よりそちらを一次成果物にする」を足した。CLAUDE.md は 59 行から 32 行になり、常時ロードの合計は 85 行になった。

skill は対象にしなかった。自作 skill で最長のものが 147 行で分割するほどではなく、200 行を超えるものは全部外部からの取り込みで、上流の更新を受ける都合上こちらでは編集しない。

## 削った文の行き先

消した 6 文のうち 3 文は、手順を書かないと対応表を先に作らないモデルにとっては必要な文である。捨てるのではなく、そういうモデルで動いているときにだけ戻すことにした。

### モデル名をどこから取るか

UserPromptSubmit hook で「今のモデルが Claude 5 世代か」を判定したい。公式の hooks reference を読むと、hook の入力で model フィールドを受け取れるのは SessionStart だけで、しかも存在は保証されず、`$CLAUDE_MODEL` のような環境変数も無い。

そこで transcript を読むことにした。hook の入力には `transcript_path` が渡され、その JSONL の assistant 行には `"model":"claude-opus-5"` のような値が残っている。最後の 1 件を取れば現在のモデルになる。`/model` でセッション途中に切り替えても次のターンから追従する。末尾 400KB を grep して 30ms 程度だった。

判定式は `claude-[a-z]+-5([^0-9]|$)` にした。世代名の直前が英字であることを要求するので、`claude-haiku-4-5` や `claude-sonnet-4-5` は名前に `-5` を含んでいても 5 世代とは判定されない。`claude-opus-5[1m]` は一致する。将来 `claude-haiku-5` が出ても列挙を更新せずに通る。

注入は 1 セッション 1 回にした。同じ文面を毎ターン積み増すと、縮めた意味がなくなる。セッション ID を名前にした marker ファイルを置いて 2 回目以降は何もしない。

判定できないときは注入しない。セッションの 1 ターン目は assistant 行がまだ無いのでモデル名が空になる。この既定によって「不明なら Claude 5 として扱う」動作になる。

### 置き場所

戻す 3 文をどこに置くか。`rules/non-claude5/` のようなサブディレクトリは使えない。`rules/` 配下は再帰的に探索され、`paths:` を持たないファイルは常時ロードされるので、そこに置くと Claude 5 でも読み込まれ、出し分けの意味が消える。`rules-non-claude5/` という別ディレクトリにして、`~/.claude/rules` には symlink せず、hook が dotfiles の実パスから直接読む形にした。

テストは 14 ケースで、注入する側に `claude-haiku-4-5-20251001`、`claude-sonnet-4-5`、`claude-3-5-sonnet-20241022`、`gpt-5-codex`、注入しない側に `claude-opus-5`、`claude-sonnet-5`、`claude-fable-5`、`claude-opus-5[1m]` を置いた。惜しい入力である haiku-4-5 と sonnet-4-5 を、負例ではなく正例 (注入する) に置いているのがこのテストの要点で、名前に 5 が入っていても補足が要る側である。

## hook が無い Codex

同じ dotfiles を Codex からも使っている。Codex は hook を実行しないので、出し分けができない。

それまで `~/.codex/AGENTS.md` は CLAUDE.md への symlink だった。これを生成ファイルに変え、CLAUDE.md と `rules-non-claude5/` を連結して書き出すスクリプトを置いた。Codex には常に強制文つきの版が渡る。生成し忘れて内容がずれるのを防ぐため、install.sh と SessionStart hook の両方から呼び、内容が同じなら書き込まない。

ここでもう 1 つ直したものがある。SessionStart で走る dotfiles の pull スクリプトが、main 以外のブランチでは早期 exit していた。worktree 上のセッションでは生成が走らない。早期 exit を git pull だけに限定し、生成とリンク更新はブランチに関係なく実行するようにした。

## 後日談: rules が Codex に渡っていなかった

2026 年 9 月 8 日、Codex 側の生成スクリプトにもう 1 度手を入れた。

`rules/` は `~/.claude/rules` への symlink 経由で Claude Code に読まれる。Codex は AGENTS.md しか読まない。つまり 7 月の時点で連結していたのは CLAUDE.md と `rules-non-claude5/` だけで、`rules/*.md` の内容は Codex に一切渡っていなかった。7 月に「同じ指示を 2 か所に書かない」と言って絵文字禁止を CLAUDE.md に寄せたのは結果的に正しくて、doc-punctuation.md 側に残していたら Codex にはその禁止が届いていなかったことになる。

連結対象に `rules/*.md` を足した。Claude Code 側で `paths:` により出し分けている rule も、Codex には全部が常に渡る。ここは Codex に hook が無い以上、今のところ諦めている。

## 残っていること

常時ロードは 139 行から 85 行になった。hook の回帰テストは 14 ケース通り、既存の hook テストも壊れていない。

削った指示はどこへ行くのか、という問いのうち、旧世代モデルの側は答えが出た。削った指示は捨てず、読むモデルを選んで戻す。

答えが出ていないのは Claude 5 世代の側で、強制文を外した 24 行の rule でも設計文の前に対応表を先に作る順序が守られるかは、実運用で数回観察して判断する、と当時の記録に書いてある。2026 年 9 月 15 日の時点で、その観察結果の記録は無い。守られていなかったときの対処も決めてあって、rule に順序を 1 文書き足すのではなく、skill の description が発火条件を捉えているかを先に見る。指示を戻す前に、指示が要らない経路を疑う順番にしたかった。
