launchd で定期実行している bash スクリプトが、`($url、作成 ...` と書いた 1 行で落ちていた。macOS 標準の `/bin/bash` 3.2 は、UTF-8 ロケールで変数名の直後に全角文字が続くと、その先頭バイトまで変数名として読む。

## 再現

2026-10-23 に手元の `GNU bash, version 3.2.57(1)-release (arm64-apple-darwin25)` で確かめた。

```console
$ LC_ALL=en_US.UTF-8 /bin/bash -c 'set -u; URL=x; echo "$URL。"'
/bin/bash: URL�: unbound variable
$ echo $?
127
```

エラーに出た変数名は `URL` ではなく `URL�` だ。`。` は UTF-8 で `e3 80 82` の 3 バイトになる。先頭の `e3` が変数名に取り込まれている。

同じ式でも、次のどれかに当てはまれば落ちなかった。

* `LC_ALL=C` で実行する
* `${URL}。` と波括弧で区切る
* `$URL (x)` のように半角スペースを挟む

展開ありのヒアドキュメントでも起きる。`「$NAME」` を含むヒアドキュメントは `NAME�: unbound variable` で止まった。

## set -u が無いと静かに壊れる

`set -u` を外すと、エラーにならずに値が消える。

```console
$ LC_ALL=en_US.UTF-8 /bin/bash -c 'URL=x; printf "%s\n" "$URL。" | xxd'
00000000: 8082 0a                                  ...
```

`x` は出力されず、`。` の残り 2 バイト (`80 82`) と改行だけが出た。未定義の変数 `URL` + `e3` を空文字に展開した結果である。画面上は文字化けした 1 文字が出るだけなので、ログを眺めても見落としやすい。

## 同じ原因で 3 回落ちた

手元の自動化スクリプト群では、この書き方による不具合を 3 回記録している。

* 2026-09-21: 調査用 loop の台帳生成が、ヒアドキュメント内の `$SECTION_NAME」` で落ちた。リダイレクト先には空ファイルが残り、以後は `-f` 判定で作成済みと扱われて見出しが書かれなくなっていた
* 2026-09-27: 監査用 loop が、PR 一覧を記録する途中の `$url、` で落ちた。09-30 にこの箇所と、記事投稿用 loop の `「$magazine」` を `${...}` に直した
* 2026-10-18: 記事投稿用 loop に、10-04 と 10-11 に書き足した異常系の分岐で同じ書き方が 3 行入っていた。レビュー未合格などの分岐で、落ちると人間への引き継ぎを記録する前に終わる

3 回目は、直した後に新しく書いたコードで再発した。しかも正常系の実行では通らない分岐なので、普段の動作確認には出てこない。

## 対策: 波括弧で書き、静的に検査する

個々の箇所は `${VAR}` に直せば済む。再発を止めるには、書き方そのものを検査する必要がある。CI は Linux の bash 5 で動いていて、この不具合は再現しなかった。実行テストでは拾えないので、perl で shell script を走査するテストを用意した。

```bash
# コメント行は実行されないので対象外にする
scan() {
  perl -ne 'next if /^\s*#/; print "$ARGV:$.: $_" if /\$[A-Za-z_][A-Za-z0-9_]*[\x80-\xff]/; close ARGV if eof' "$@"
}
```

`$` に続く変数名の直後に `0x80` 以上のバイトがあれば検出する。走査対象は `git ls-files '*.sh'` の全ファイルだ。検出器自身にも、`$URL。` を検出し、`${URL}。` とコメント行を検出しないテストを付けた。

launchd から起動するスクリプトは、shebang が `#!/usr/bin/env bash` でも、この環境では `/bin/bash` 3.2 で動いていた。日本語のメッセージを組み立てるスクリプトでは、全角文字の直前の変数を `${VAR}` で書く。CI が Linux だと手元と bash の版が違うため、上の静的検査を CI に足す変更を出した (2026-10-23 時点でレビュー待ち)。
