手元の Mac では、Codex と Claude Code に作業を任せる時間が長くなってきた。困っていたのは、Codex が sandbox の外に出たいときに出す権限拡大の要求である。Codex の設定では `approvals_reviewer = "auto_review"` にしていて、要求のたびに guardian と呼ばれる自動審査が通すかどうかを判定する。人の承認では止まらないものの、判定が挟まるぶん作業は細切れになる。

どこまで sandbox を広げてよいかを、勘ではなく記録から決めたかった。2026-11-03 に、直近 2 週間の Codex の記録を集計してから設定を変えた。同じ日に Claude Code の auto mode の規則も書き足している。

## 2 週間で 2,053 件、拒否は 11 件

集計の対象は 2026-10-20 から 11-03 までの Codex の記録である。権限拡大の要求は 2,053 件あった。内訳の大きいものを並べる。

| 要求の種類 | 件数 |
|---|---|
| 作業ディレクトリとは別のリポジトリへの書き込み | 822 |
| 通信系 | 約 450 |
| `~/.cache` への書き込み | 94 |
| Obsidian の vault への書き込み | 93 |

guardian の判定は同じ期間に 1,637 件あり、allow が 1,626 件、deny が 11 件だった。allow の割合は 99.3% になる。

要求の大半は、通信と作業ディレクトリの外への書き込みの 2 種類に集まっていた。guardian はそのほとんどを通しており、毎回判定させてもほぼ同じ答えが返ってくる種類の要求だったことになる。

## sandbox の中で 2 種類を許可する

`~/.codex/config.toml` に足したのは次の行である。既存のキーは変えていない。

```toml
approval_policy = "on-request"
sandbox_mode = "workspace-write"

# 自走を優先する。2026-10-20〜11-03 の権限拡大 2,053 件の大半が通信と cwd 外への書き込みで、
# guardian の判定は 99.3% が allow だったため、その 2 種を sandbox 内で許可する。
[sandbox_workspace_write]
network_access = true
writable_roots = [ "~/repos", "~/Documents/remoteVault", "~/.cache" ]
```

`writable_roots` の実際の値はホームディレクトリを展開した絶対パスで書いている。`approval_policy` と `sandbox_mode` は、意図を設定ファイルに残すために明示した。`approvals_reviewer = "auto_review"` はそのまま残しているので、ここに挙げた以外の権限拡大は引き続き guardian が判定する。

設定ファイルのコメントに集計の期間と割合を書いたのは、後で読んだときに「なぜこの 3 か所だけなのか」を設定ファイルの中で答えられるようにするためである。

## 採らなかった 3 つの案

広げ方には、もっと大きく開ける案もあった。

1 つ目は `approval_policy = "never"` にする案である。承認を一切求めない設定に見えるが、この値では権限拡大そのものができなくなる。作業ディレクトリの外に触る作業は、承認待ちで止まる代わりに失敗で止まる。自走を増やすつもりが、かえって減らすことになるため採らなかった。

2 つ目は `danger-full-access` で sandbox を外す案である。手元では、取り消せない操作を止めるために Omnigent というツールのポリシーも併用している。ただし、Codex Desktop と、定期実行の loop から呼ぶ `codex exec` は Omnigent を経由しない。この 2 つの経路で sandbox まで外すと、取り消せない操作を止める仕組みが何も残らない。

3 つ目は `~/.config` も `writable_roots` に入れる案である。入れると、エージェントが自分の設定を審査なしで書き換えられるようになる。2 週間の記録でも `~/.config` への要求は 18 件だけで、審査を外す利点が小さかった。

## 変えたあとの確認

`codex exec` で 2 つの操作を試した。curl は HTTP 200 を返し、`~/.cache` への書き込みは exit 0 で終わった。そのセッションの turn_context には `network_access=true` と `writable_roots` が反映されていた。`require_escalated` を伴うツール呼び出しは 0 件で、guardian のセッションも 0 件だった。

戻すときは、変更前の `config.toml` を退避したファイルで上書きすれば元に戻る。

## Claude Code 側は既定を残して書き足す

同じ日に、Claude Code の auto mode の設定も見直した。auto mode では、操作を許可するか止めるかを分類器が判断する。その判断材料として、`~/.claude/settings.json` の `autoMode` に環境の説明 (`environment`) と許可の規則 (`allow`) を書ける。

ここでは組み込みの既定 (`"$defaults"`) を残し、その後ろに書き足す形にした。`claude auto-mode config` で反映後の件数を確かめると、`environment` 27 件、`allow` 20 件、`soft_deny` 72 件、`hard_deny` 1 件だった。

`environment` には、個人の Mac であること、自分の 2 つの GitHub 組織を信頼済みのソース管理として扱うこと、そのうち片方には公開リポジトリもあり得ることを書いた。顧客や勤務先の組織は機密として扱うことと、dotfiles・vault・ハーネスの状態ファイルの位置づけも書いている。

`allow` に足したのは 4 種類である。

- dotfiles の main への自律的な編集と push
- 個人の組織のリポジトリで、そのリポジトリ自身の origin への push と PR の作成
- vault のノート 1 件単位の作成・編集・削除
- 決められたディレクトリのスクリプトを実行する launchd ジョブの登録と編集

どの項目にも除外条件を付けた。たとえば dotfiles の項目では、force push、エージェント自身の権限を広げる変更、秘密情報や顧客・勤務先の資料のコミットを対象外にしている。

### 設定ファイルは自分では書けなかった

候補の設定を settings.json に書き込もうとしたところ、auto mode の Self-Modification の規則で止まった。エージェントが自分の権限設定を書き換える操作として扱われたためである。そこで候補ファイルを別に作り、本人が `cp` で適用した。Codex 側で `~/.config` を外した理由と同じ線引きが、Claude Code 側では既定の規則として先に効いていた。

### critique を 2 回かけて 3 版目で止めた

書いた規則は `claude auto-mode critique` で点検した。分類器から見て規則がどう読めるかを講評するコマンドである。2 回実行して指摘を反映し、3 版目で打ち切った。2 回目の講評の総評は、規則同士の矛盾は無いというものだった。ただし、境界の書き方には具体的な指摘が残った。

- 信頼する組織を「個人の組織」と書くだけでは、信頼境界の内側だと読まれない場合がある。境界の内側であることを明記する
- launchd の規則が最もリスクが高い。エージェントがスクリプトを書き、それを定期実行に登録できるからである。`ProgramArguments` をインタプリタとスクリプト 1 本に固定する
- 承認を無効にしてエージェントを起動するジョブ (`--dangerously-skip-permissions` など) を除外条件に名指しする
- vault は Obsidian Sync でクラウドへ同期されるので、第三者の個人情報を書き込む操作も除外する

3 版目では、信頼境界の明記を `environment` に、残りを `allow` の除外条件に入れた。launchd の項目は「インタプリタ (`/bin/bash` か `/bin/zsh`) と許可したディレクトリのスクリプト 1 本だけ」を条件にした。インラインのコマンドや、認証情報を読むスクリプトは対象外にしている。

## まだ測っていないこと

この記録の時点で確かめたのは、設定が反映され、通信と `~/.cache` への書き込みが承認なしで通ることまでである。適用後の数日で権限拡大の要求や guardian の判定がどれだけ減ったかは、まだ集計していない。次に同じ集計をかけ、2,053 件の内訳のうち通信と外部への書き込みが消えているかを見る。Claude Code 側の 4 種類の `allow` が実際にどれだけ止まる回数を減らしたかも、同じく未測定である。
